The two pillars, defined

These are the co-equal differentiators the landscape leaves open. Every tool below is scored against them.

Path intelligence pillar 1

  • Type accuracy — is a mount a host bind, a named Docker volume, an anonymous/container-only path, or a network (NFS/CIFS/SMB) path? Correctly, before deploy.
  • Existence awareness — does the referenced host path already exist, and does the tool refuse to erroneously create it (the Portainer / Docker-CLI footgun)?

Backup integrity pillar 2

  • Application-consistent — databases quiesced or logically dumped, not raw copies of live files.
  • Full coverage — named volumes and bind/host paths of any stack, not just managed DBs or the tool's own config.
  • Remote + retention — off-box destinations on a schedule with rotation.

Closest contenders — and exactly where each falls short

Four tools get one pillar substantially right. None gets both, and none guards host-path existence.

best path typing

Dokploy

The only manager with genuinely typed mount forms — Volume / Bind / File as distinct UI objects — plus real DB dumps and named-volume backup.

Misses: bind-mount data is explicitly excluded from backup; DB dumps cover only managed databases; no network-path type; no existence check.
best backup breadth

Cosmos

Restic-backed backups of both named volumes and binds, to any Rclone remote, with cron + retention + encryption. Explicit bind-vs-volume typing.

Misses: backup is only file-consistent via optional container-stop — no DB dump/quiesce; no anonymous/network typing; no existence guard.
best DB-consistency (Docker)

Runtipi

Stops apps before backup for genuine app-consistency, on a schedule with retention and one-click restore.

Misses: local-only (no remote); named-volume coverage unverified; only partial typing; no existence guard.
most integration-shaped

offen · Bivac

offen gives volume+bind+remote+encryption with dump hooks; Bivac even auto-detected DB datadirs and dumped them — the exact pattern we want.

Misses: offen wires every dump by hand per container and has no UI; Bivac is abandoned (~2020). The integrated version was never sustained.

The gap Yard Dog fills

The capability isn't missing — the integration is. Every primitive already ships somewhere: logical DB dumps (offen, resticker, Bivac, Coolify/Dokploy for managed DBs), stop-and-copy quiescence (Nautical, Runtipi, Cosmos), and encrypted remote storage with retention (restic, Duplicati, Rclone backends). What no maintained tool combines:

  • Path-type intelligence as a first-class model — host bind vs named volume vs anonymous vs network (NFS/CIFS/SMB). Today the ceiling is a bind-vs-volume toggle; network paths are typed nowhere.
  • Existence as a safety guard — tell the operator whether a host path exists and refuse to silently mkdir it. Only Podman/CapRover/Dokku avoid the footgun, and none surfaces it as a deliberate UX; the rest inherit Docker's root-owned auto-create.
  • Automatic, topology-aware DB backup — detect "this container is Postgres → dump it" across an arbitrary Compose stack, covering both its volumes and its binds, to a remote target — instead of hand-wiring a docker exec pg_dump per service or being limited to the tool's own managed databases.

In one line: the market splits path-typing tools, DB-dump tools, and volume-backup tools into three piles — Yard Dog is the first to hold all three, safely, over the stacks a self-hoster actually runs.
